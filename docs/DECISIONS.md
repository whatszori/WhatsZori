# Decisions

One line each, with the reason.

- `dev` was created as an orphan branch: the remote repo was empty, so there was no `main` commit to branch from, and committing to `main` was off-limits.
- `MEMORY.md` (personal working notes) is in `.gitignore` so it never lands in the repo by accident.
- Stack versions are whatever was current at scaffold time (Vite 8, TS 6, ESLint 10, Vitest 5); React stays on 18.3 since the brief says 18+ and 18 is the safest WebView2/WebKitGTK baseline.
- `npm run test` goes through `scripts/vitest.mjs`: on Windows a lowercase drive letter in cwd makes Vitest load twice and every suite fails; the wrapper uppercases it.
- Theme accent is stored as a preset id or a custom hex. Presets have a light and a dark variant, so one choice looks right in both themes; a custom hex is used as-is in both.
- Hover, active, soft and bubble-out shades are derived from `--wz-accent` with `color-mix()`, so a theme or the OS only has to set one variable.
- Avatar tints use a fixed set of 9 hues at low saturation (set per theme via `--wz-avatar-*`), which avoids the rainbow look and keeps contrast predictable.
- Tooltip wraps its trigger in an inline-flex span instead of `cloneElement`, to avoid ref juggling that the react-hooks compiler rules flag.
- One global layer stack (`ui/layers.ts`) owns Esc: it listens in capture phase and closes only the topmost menu, popover or dialog, so Esc in the composer only cancels reply/edit when nothing is open.
- Ctrl is matched as Ctrl *or* Cmd, so the same shortcuts work in a future macOS build.
- Backend is a `Backend` interface grouped into services (`auth`, `chats`, `messages`, `privacy`, `settings`) plus `on(event)`, matching how Wails binds Go services. UI code only imports `backend` from `src/api`; swapping the mock for Wails bindings is a one-file change in `api/index.ts`.
- Message identity is a local `pk` (numeric string from our own store), not the WA message id, because WA ids aren't unique across chats. Pages are fetched with `beforePk`.
- The mock persists login state, settings and ghost mode to `localStorage` (so reloads keep you logged in), but chats and messages are regenerated from a fixed seed on each load. That keeps screenshots reproducible.
- `?demo=1` turns on the event simulator, the demo plugin registrations and a small dev panel (simulator toggle, fake connection state). Without it the app is quiet.
- The simulator prefers the chat that was last opened (the mock treats `markRead` as "the user is looking at this"), so live edits and deletes show up where you're looking. The conversation calls `markRead` on every open for this reason; the real backend can no-op it when there's nothing unread.
- Message "tail" is a tighter corner on the last bubble of a run rather than a drawn tail shape. It reads as a tail but stays quiet.
- Day separators: inline pills in the list plus a floating "current day" pill that shows only while the user scrolls. True sticky headers don't combine well with a virtualized, measured list.
- Older messages load when scrolled within 600px of the top; scroll position is restored from "distance from bottom", which works with measured, variable-height rows.
- Quote click: loads older pages until the target is in memory (`ensureLoaded`), then centers and flashes it.
- Mock edit window is 15 minutes, like WhatsApp; Up arrow on an empty composer only edits your last text message inside that window.
- Delete for everyone asks for confirmation in a dialog. The dialog text admits that clients with anti-delete (like this one) may still show it.
- Settings is a full view in the main pane, with the chat list still visible on the left. Esc and Ctrl+, close it.
- Plugin-facing types (`plugin-core/types.ts`) only import `ComponentType` from React. Plugins get narrow `PluginMessage` / `PluginChat` shapes built by adapters, not our internal DTOs, so internals can change without breaking plugins.
- The `settings.sections` slot renders inside Settings → Plugins under "Plugin settings", and that group is hidden when nothing registered.
- The QR code is a fake grid with the right look (finder patterns, quiet zone), drawn as SVG. It stays dark-on-white in dark mode because phones scan inverted codes poorly. Clicking it simulates a scan in the mock.
- The emoji button opens a small fixed grid; a real picker is out of scope for this pass.
- Attach and "Open folder" buttons are present but do nothing until the Go side exists.
- External links in messages use `target="_blank"`. Under Wails they'll need to go through `BrowserOpenURL`, which is a backend concern.
- Two ESLint warnings remain from `react-hooks/incompatible-library` on `useVirtualizer` (TanStack Virtual can't be memoized by the React Compiler). They're warnings, not errors, and expected for that library.
- Screenshots were taken with `playwright-core` driving the system Edge install (no browser download), from a script kept outside the repo so the project has no Playwright dependency.
- Themes are packages: a folder with `manifest.json` and CSS modules. A module can be required, on by default, or off by default; the user's per-module choices live in `settings.themeModules` as `themeId/moduleId`. Splitting a theme this way lets people take, say, Adwaita's widgets without its header bars.
- Built-in themes are bundled with `import.meta.glob(..., { query: '?raw' })` so they work offline in the Wails binary. User themes from disk will arrive from Go in the same `ThemePackage` shape.
- Theme CSS is injected as `<style data-wz-theme>` at the end of `<head>`, so it wins over app CSS at equal specificity without `!important`.
- A user-picked accent (inline on `<html>`) still beats a theme's accent. With no accent picked, the theme's accent is used, and the Appearance page says so instead of highlighting a preset.
- Adwaita uses blue_4 (`#1c71d8`) as its light accent rather than `#3584e4`, so white text on it passes WCAG AA. Accent bubbles are darkened for the same reason.
- WinUI theme: Mica and acrylic are drawn with their solid fallback colors, because the brief rules out blur and translucency. The real Mica backdrop would come from the Wails window (WebView2 transparency), not from CSS.
- WinUI follows Fluent's accent rules: AccentDark1 (`#005fb8`) with white text in light mode, AccentLight2 (`#60cdff`) with black text in dark mode. Accent bubbles use `--wz-accent-fg`, so they switch text color the same way.
- In the WinUI dialog, the destructive action is the accent (primary) button on the left, as in ContentDialog; the close X is hidden when the dialog has its own buttons.
- Several themes can be on at once. They're applied in name order (Adwaita, then WinUI), so the later one wins where they overlap. Mixing modules from different themes works but isn't curated.
- Layout is a separate appearance setting (`panels` / `rail`), set as `<html data-layout>`, not part of a theme. Moving settings into the sidebar and adding an icon rail changes the component tree, which CSS can't do. A theme can ask for a layout with `"layout"` in its manifest, and turning the theme on switches to it once; the user can switch back.
- Rail layout: Chats, Calls, Status, Archived at the top; Settings and profile at the bottom. Calls and Status are honest "not supported yet" panels rather than missing icons, so the rail reads like the familiar one without pretending features exist.
- The rail unread badge counts chats with unread messages (not muted or archived), like the official client, not total messages.
- "New chat" (+) focuses the search field: there's no contact picker yet, and the search placeholder already says "Search or start a new chat".
- The chat list ⋮ menu only has actions that work (archived, mark all read, settings, log out). New group, starred messages, select chats and app lock were left out rather than shown dead.
- Classic Green copies the layout, palette and bubble shapes of the official desktop client but not its logo, name or doodle wallpaper (their artwork); it uses our own dot pattern instead. The light accent is darkened to `#178048` so white text on it passes AA.
- Avatars for names that are just a phone number show a person silhouette instead of digits.
- Profile (your name, about, phone) is its own settings section and backend service (`profile.get/setName/setAbout`), separate from About (app version, disclaimer, links). `Me` in auth stays the account identity; `Profile` is what others see.
- The rail avatar opens Profile directly (`openSettings('profile', true)`); the settings gear opens the section list.
- Profile fields edit in place. While editing, Esc cancels the edit only (the field registers its own layer), a second Esc leaves the page.
- Contact / group info is a panel to the right of the conversation, opened by clicking the header (or ⋮ → Contact info). Under 1100px wide it floats over the conversation instead of squeezing it. It closes when you switch chats and on Esc.
- Info data comes from a new `chats.getInfo(jid)`: about/description, phone, members with admin flags, media/doc/link counts, the 6 latest photos/videos, and counts of what anti-delete and edit history kept. It's refetched when the chat's last message changes.
- The info panel only offers actions that work today: mute, pin, archive, jump to media, open a member's chat, member search. Block, report, clear/export chat, leave group, disappearing messages and invite links need the Go side and were left out rather than shown dead. Instead there's a "Kept by WhatsZori" section with the anti-delete and edit-history counts for the chat.
- Vitest turns CSS imports (even `?raw`) into empty strings, so the theme test only checks that every file a manifest lists exists.
- Logo: a message bubble (rounded square, tail on the right, so it doesn't echo the round WhatsApp bubble) with a monoline Z whose bottom bar is a horizon and an amber sun rising behind it ("zori" = dawns). Slate blue `#3d6fb4` (the default accent) and amber `#f5b860`, no green. Files in `frontend/public/`: `logo.svg` (mark, also the favicon), `avatar.svg` (circular, for profile pictures), `logo-wordmark.svg` (mark + name; follows light/dark via `prefers-color-scheme`), plus PNG exports at 32/192/512 px and the wordmark in light and dark.
- The wordmark letters are hand-drawn monoline strokes matching the Z, not text, so it looks the same everywhere without bundling a font.
- In the app, the logo is an inline `<Logo />` component (copies of the `public/` drawings), not an `<img>`: an SVG image only sees the OS color scheme, so a manually chosen dark theme would get dark lettering on a dark background. Used on the splash, auth card, sidebar header (panels layout), empty state and About.

## Desktop shell (Wails)

- Wails **v3.1.0**, not v2: v3 went stable (v3.0.0 on 2026-10-26, v3.1.0 on 2026-11-01), which was the condition for using it. The v2 names in the plan map to v3 like this: `wails dev/build` → `wails3 dev/build`, `wails.json` → `build/config.yml` + Taskfiles, `wailsjs/` → `frontend/bindings/`, `runtime.EventsEmit` → `app.Event.Emit`, `AssetServer.Handler` → `AssetOptions.Middleware`, `frontend:dev:serverUrl: auto` → `dev_mode` + `WAILS_VITE_PORT`.
- Linux targets GTK4 + WebKitGTK 6.0, because Wails 3.1 removed the GTK3 / webkit2gtk-4.1 stack. The v2 `webkit2_41` tag doesn't exist in v3, so it isn't used.
- The Go module is at the repo root (`github.com/whatszori/WhatsZori`). `go test ./...` also lists a Go package that ships inside `frontend/node_modules` (flatted). It has no tests and is harmless; scripts and CI use `. ./internal/...`.
- `frontend/dist/.gitkeep` is committed and restored after every Vite build (`emptyOutDir` deletes it), so `//go:embed all:frontend/dist` compiles on a fresh clone.
- The generated bindings (`frontend/bindings/`) are committed, so frontend typecheck, lint and build work without Go. ESLint and Prettier ignore that folder.
- The Wails backend is a separate lazy chunk loaded with top-level `await import()`. In a browser, `@wailsio/runtime` is never evaluated (it logs a warning on load). Detection is the same native-bridge check the runtime uses (`chrome.webview` / `webkit.messageHandlers.external`), with `?backend=mock` as an override.
- Hybrid backend: Go handles system, settings, system theme, user themes and window. Auth, chats, messages, profile and privacy delegate to the mock, and settings writes are mirrored to the mock because it reads the history settings for its own behaviour.
- `Backend` grew `kind`, `system`, `systemTheme`, `userThemes` and `window`, so "is this the desktop app" is a property of the backend, not a separate global.
- Settings are one JSON file of top-level keys, each with one owner. `app` is the frontend's `AppSettings` and `window` is Go's window state, which the frontend can't overwrite. Writes go to a temp file, then a rename. A leading BOM is ignored (Notepad/PowerShell add one), and an unreadable file is kept as `settings.json.broken-<time>` instead of being lost.
- On the first desktop start, Go has no `app` key yet, so the desktop app takes over the mock's localStorage settings once.
- Sidebar width moved from its own localStorage key into `AppSettings.ui.sidebarWidth`, so it's stored by Go in the desktop app like everything else.
- Event payload types are hand-written in `src/api/events.ts`. A Go test checks the names, and `src/api/wails/check.ts` fails `tsc` if the keys drift from the generated models. `tygo` wasn't needed, because the v3 generator already emits the models.
- Events are registered with `application.RegisterEvent[T]`, so Wails type-checks every emit and the generator sees them.
- The window starts hidden. The saved bounds are applied, or dropped if less than 120×20 px of the title bar would land on a connected screen's work area, and then the window is shown. That avoids a visible jump from the centre.
- Normal (unmaximised) bounds are tracked on move/resize, so closing while maximised still remembers the size to restore to.
- No white flash: the asset middleware adds `data-theme` to the index page's `<html>` before any CSS runs, and the native background uses the page background the frontend last reported (`Window.SetTheme(dark, bg)`). This also covers themes that change `--wz-bg-app`. The default `#e9e9eb` / `#121214` is used only until then.
- The Windows title bar is set from the *app* theme, not the OS. The window is created with an explicit Light/Dark, never SystemDefault (with that, Wails would flip it back on OS changes). Later switches call DWM directly (`w32.SetTheme`), because Wails only applies the theme at creation.
- In the desktop app, the "System" theme uses Go's scheme rather than `prefers-color-scheme`. WebView2's media query follows the window theme we set, so it would just echo our own choice.
- `AccentFg` is WCAG contrast with a 10% head start for white. Pure WCAG picks black on Windows' default blue `#0078d7` (4.67 vs 4.50), and every OS uses white there.
- The system accent sets `--wz-accent-fg` inline. Presets and custom colors keep the theme's `--wz-accent-fg` as before.
- Windows: one goroutine waits on `RegNotifyChangeKeyValue` for both keys plus a stop event. Notifications are coalesced for 150 ms (Settings writes several values per change), and an event is sent only when the palette actually changed.
- Linux: the session bus is only dialled if `DBUS_SESSION_BUS_ADDRESS` or `$XDG_RUNTIME_DIR/bus` exists, so godbus never tries to autolaunch a bus. Connect and calls time out after 2 s. GNOME accent names map to libadwaita's hex values. The gsettings fallback doesn't watch for changes, because that would need a long-running `gsettings monitor`.
- macOS is a stub that reads `AppleInterfaceStyle` with `defaults`.
- Disk themes are single `.css` files with a header comment. That's simpler than the bundled manifest packages, and it's what people drop into a folder. One file theme is active at a time (`AppSettings.userTheme`), on top of any bundled themes. Metadata is parsed in Go, so `Themes.List()` returns it ready to show.
- The user theme is a `<link>` kept as the last element of `<head>`. On a change, the new `?h=<hash>` link loads next to the old one, and the old one is removed on `load`, so there's no unstyled flash.
- The theme watcher debounces per file (100 ms). The payload hash is the first 12 hex characters of SHA-256 and is empty when the file was deleted.
- Asset paths: `SafeRel` rejects the obvious and Windows-specific tricks (backslash, `:`, trailing dot or space, device names, `..`, empty segments), then `os.Root` does the real containment, including symlinks. Content types come from a fixed table because on Windows `mime` reads the registry, which sometimes maps `.js` to `text/plain`. Themes are `no-store`; plugins are `no-cache` (revalidate).
- The middleware answers `/wails/custom.js` (an optional script the Wails runtime always probes for) with an empty script, so the console has no 404 on every start.
- Boot sentinel: the marker is written only after `application.New` returns. Wails exits a second instance inside `New`, and writing earlier made the second launch leave a marker behind, which turned the next real start into safe mode.
- A start that closes before `BootOK` (about 4 s after mount) counts as failed, on purpose. A UI broken by a plugin usually gets closed quickly too. Safe mode lasts one start.
- `OpenExternal` only allows http(s) and mailto. Message text is untrusted, and `file:` or custom protocol links could launch programs. In the desktop app, clicks on off-origin links are intercepted and opened in the system browser, instead of letting WebView2 open a second webview.
- `WHATSZORI_CONFIG_DIR` overrides the config folder, and `WHATSZORI_WEBVIEW_DEBUG_PORT` opens DevTools for Playwright. WebView2's own `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` is ignored because Wails always passes arguments of its own.
- The app icon is the bubble logo, `frontend/public/logo.svg`, rendered to a 1024 px transparent `build/appicon.png` (headless Edge screenshot). The `.ico` is generated from that PNG, so after changing the logo, re-render the PNG and run `wails3 task common:generate:icons`.
- Build assets were regenerated with `wails3 update build-assets` from `build/config.yml`. The macOS, iOS, Android, Docker and MSIX templates were left out (no target yet), and the Windows installer is NSIS.
- Vite binds `127.0.0.1`: the Wails dev proxy dials IPv4 only, and Node may bind `localhost` to `::1` on Windows.

## WhatsApp backend

- whatsmeow is the latest commit at the time (`v0.0.0-20261116172437-19d61352436f`). Every signature was checked against the module source; most network calls now take a `context.Context`.
- SQLite is `modernc.org/sqlite` (pure Go, so the Windows build stays CGO-free). FTS5 works with it, so search uses FTS5, not `LIKE`.
- Two databases: `session.db` is whatsmeow's `sqlstore` and nothing of ours touches it; `whatszori.db` is ours. Logging out or a broken session can't take the message history with it.
- `whatszori.db` runs in WAL with `foreign_keys`, `busy_timeout` and `_txlock=immediate`, set through the DSN so every pooled connection gets them. Immediate transactions avoid the busy errors deferred ones hit when two writers both try to upgrade a read lock.
- Migrations are numbered `.sql` files embedded in the binary. Each runs in a transaction together with its `PRAGMA user_version` bump. A db with a higher version than the build knows is refused rather than used half-understood.
- Data access is plain `database/sql` in `store/repo`, every function taking a `DBTX` (`*sql.DB` or `*sql.Tx`). sqlc would have added a code generator to the toolchain for about 40 queries.
- Settings stay in the existing `settings.json`, not a `settings` table: the Wails task already built atomic writes, BOM handling and broken-file recovery there, and the frontend's `AppSettings` lives in it. Go reads `app.history` from it; ghost mode is a new Go-owned `privacy` key.
- Reactions and receipts are keyed by `(chat_jid, msg_id)`, not by message pk, with no foreign key: they often arrive before the message (history order, retries) and attach once it shows up.
- Timestamps are unix milliseconds everywhere, matching what the frontend already used.
- Store kinds are finer than UI kinds (`audio`, `location`, `contact`, `poll`, `unknown`). The DTO maps location, contact and poll to `text` with a preview line ("📍 …", "👤 …", "📊 …") and audio to `voice`, so the existing bubbles render them without new components.
- Unknown message types are stored with kind `unknown` and the raw proto and show "This message type isn't supported yet". Pure control or meta messages (sender key distribution only, protocol messages, poll votes, pin/keep-in-chat) aren't stored as messages.
- `contentUnknown` is derived, not stored: a deleted or placeholder row with no raw proto and no body. A placeholder whose content arrived later keeps `is_placeholder = 1` (we still know the revoke came first) but stops being content-unknown.
- Revoke kind is `admin` when the stanza's edit attribute says admin revoke (`8`) or the revoker isn't the original sender; otherwise `sender`.
- With "keep deleted messages" off, a revoke drops the body, raw proto, media file and edit history, but keeps the row so the "deleted" marker still shows where the message was.
- Edits from anyone but the original sender are ignored and logged (message ID, redacted JIDs). An edit that arrives late (older than the current version) is added to the history but doesn't replace the newer text.
- Live edits arrive as `ProtocolMessage{MESSAGE_EDIT}`; history sync hands them over already unwrapped by `ParseWebMessage` (original id, new content, `IsEdit`). Ingest handles both.
- `SynchronousAck` is on. whatsmeow's default acks before handlers finish; with it on, the ack goes out after our SQLite write, and the handler returns false on a db error so there's no ack at all and the server redelivers.
- Frontend events go through a batcher (50 ms or 200 items). Consecutive `msg:batch` events merge, a `chat:update` for a chat that's already queued replaces that snapshot in place, and everything else keeps its order.
- History messages are stored with `read_sent = 1`, so switching ghost mode later never fires receipts for months of old messages; unread counts come from the conversation's `unreadCount`. Pending receipts are also capped at the last 7 days and 300 messages.
- Only live messages are auto-downloaded, never history. Auto-download covers photos, voice notes and stickers up to 16 MB, which is what tends to get deleted and is cheap to keep; videos and documents download when opened.
- "Download media automatically" now defaults to on (it was off in the mock), so a deleted photo survives without the user changing anything.
- Media files are named by the SHA-256 of their content (WhatsApp's `fileSHA256`, or our own hash) in two-character shard folders. A forwarded photo is stored once, and a URL's bytes never change, so `/wz-media/` responses are cached as immutable.
- `/wz-media/<pk>` downloads on demand inside the request (60 s timeout, one download per pk however many requests wait for it) and falls back to the stored thumbnail with `no-store`. A 403/404/410 from the CDN marks the file `expired`, and it isn't retried.
- Media is served with `nosniff` and a sandboxing CSP, and only known image, video, audio and PDF types are served inline. Anything else (HTML, SVG, scripts) is an `application/octet-stream` attachment: it's other people's content on our webview's origin.
- Canonical JIDs: the phone-number JID when the LID mapping is known, the LID otherwise, never a device suffix. When a mapping shows up later (`SenderAlt`, contact sync, history mappings), the LID chat is merged into the phone-number chat, and a new `chat:removed` event tells the UI to drop the old row.
- The privacy gate holds the only `PresenceTransport`; the `wa.Client` interface everything else uses has no `SendPresence`, `SendChatPresence` or `MarkRead`. A test walks the AST of every non-test `.go` file and fails if anything outside the gate and the whatsmeow adapter calls them.
- "Hide online" sends `unavailable` on connect and never `available`. Read receipts: `always` sends them when a chat is opened, `never` never does (the local unread count still clears), `on-reply` sends them just before our next message to that chat. In groups there's one receipt per sender, with the participant set.
- Anti-spam limits: 60 messages a minute, 12 different chats a minute, and the same text (whitespace and case normalized, 12+ characters) to at most 4 chats in 10 minutes. A fast typist in one chat doesn't get near them, and "thanks!" to several people isn't blocked. A blocked message is never stored; the reason comes back as the call's error and shows as a toast.
- Sending is optimistic: the message is stored as `pending` and returned at once, and the network part runs in the background. A failure sets `failed` and emits a `toast` event. Refusals before anything is stored (offline, rate limit) come back as errors, and the composer gets its text back.
- Edits are refused on the Go side after whatsmeow's `EditWindow` (20 minutes); the UI already hides the option after 15.
- Our own edits, revokes and reactions go through the same ingest code as incoming ones (`ApplyLocal*`), since whatsmeow doesn't echo what we send. One code path, one set of tests.
- Media sending: JPEG and PNG up to 16 MB go as photos, everything else (and bigger images) as documents, up to 100 MB. The file is picked with the native dialog on the Go side, so the bytes never cross the webview bridge. Voice notes were cut.
- `wa` doesn't import `ingest`, `privacy` or `antispam`; the sender takes small interfaces. That keeps the package graph acyclic, and the send tests (an external `wa_test` package) run against the real ingester, gate and limiter.
- `WHATSZORI_NO_CONNECT=1` keeps the client offline (no QR, no reconnect), so a build can be smoke-tested without talking to WhatsApp. The auth screen then shows the reason and a retry button instead of a code.
- whatsmeow's logs go to slog with every run of 6+ digits masked, and its debug level is dropped (it dumps whole stanzas). Our own logs carry message IDs and event types; JIDs go through `redact.JID`.
- Statuses (`status@broadcast`) and newsletters are skipped: the UI has no place for them yet.
- "Delete for me" from another of your devices is ignored. Keeping what was on screen is the point of this client, and Settings has "Delete local data" for a clean slate.
- Logout keeps `whatszori.db` and the media. Settings → About has a separate "Delete local data" (with a confirmation) that logs out, then empties our tables and the media folder.
- The login QR is rendered with `uqr` (MIT, no dependencies) as one SVG path with error correction L, like WhatsApp Web. The fake QR is gone; the mock's random code renders as a real QR too.
- Toasts are a small store plus one component: bottom centre, at most three, deduplicated, gone after 5–7 s. There was no toast UI before.
- Typing notifications: `composing` at most every 8 s while keys are pressed, `paused` after 5 s idle, on send, and on leaving the chat.
- `auth.getConnState()` was added because `conn:state` events emitted before the UI subscribed are lost; the UI asks once on start.
- Avatars: the ~96 px preview from WhatsApp for small avatars, the full picture from 72 px up (info panel, profile). The picture id is sent back on refresh, so an unchanged picture costs one small request and no download. At most three requests run at once, and "no picture" / "hidden" answers are cached for a day too, so scrolling the chat list doesn't hammer WhatsApp.
- Avatar pictures are only fetched from `https://*.whatsapp.net`, served as `image/jpeg` with `nosniff`, and cached by the webview for an hour; `avatar:changed` adds `?v=n` to force a reload. The frontend remembers 404s per URL, because the virtualized chat list remounts avatars constantly.
- The picture fades in over the initials only after it has loaded, so a slow or missing picture never shows an empty circle.
