# Decisions

One line each, with the reason.

- `dev` was created as an orphan branch: the remote repo was empty, so there was no `main` commit to branch from, and committing to `main` was off-limits.
- `MEMORY.md` (personal working notes) is in `.gitignore` so it never lands in the repo by accident.
- Stack versions are whatever was current at scaffold time (Vite 8, TS 6, ESLint 10, Vitest 5); React stays on 18.3 since the brief says 18+ and 18 is the safest WebView2/WebKitGTK baseline.
- `npm run test` goes through `scripts/vitest.mjs`: on Windows a lowercase drive letter in cwd makes Vitest load twice and every suite fails; the wrapper uppercases it.
- Theme accent is stored as a preset id or a custom hex. Presets have a light and a dark variant, so one choice looks right in both themes; a custom hex is used as-is in both.
- Hover, active, soft and bubble-out shades are derived from `--wz-accent` with `color-mix()`, so a theme or the OS only has to set one variable.
- Avatar tints use a fixed set of 9 hues at low saturation (set per theme via `--wz-avatar-*`), which avoids the rainbow look and keeps contrast predictable.
- Tooltip wraps its trigger in an inline-flex span instead of `cloneElement`, to avoid ref juggling that the react-hooks compiler rules flag.
- One global layer stack (`ui/layers.ts`) owns Esc: it listens in capture phase and closes only the topmost menu, popover or dialog, so Esc in the composer only cancels reply/edit when nothing is open.
- Ctrl is matched as Ctrl *or* Cmd, so the same shortcuts work in a future macOS build.
- Backend is a `Backend` interface grouped into services (`auth`, `chats`, `messages`, `privacy`, `settings`) plus `on(event)`, matching how Wails binds Go services. UI code only imports `backend` from `src/api`; swapping the mock for Wails bindings is a one-file change in `api/index.ts`.
- Message identity is a local `pk` (numeric string from our own store), not the WA message id, because WA ids aren't unique across chats. Pages are fetched with `beforePk`.
- The mock persists login state, settings and ghost mode to `localStorage` (so reloads keep you logged in), but chats and messages are regenerated from a fixed seed on each load. That keeps screenshots reproducible.
- `?demo=1` turns on the event simulator, the demo plugin registrations and a small dev panel (simulator toggle, fake connection state). Without it the app is quiet.
- The simulator prefers the chat that was last opened (the mock treats `markRead` as "the user is looking at this"), so live edits and deletes show up where you're looking. The conversation calls `markRead` on every open for this reason; the real backend can no-op it when there's nothing unread.
- Message "tail" is a tighter corner on the last bubble of a run rather than a drawn tail shape. It reads as a tail but stays quiet.
- Day separators: inline pills in the list plus a floating "current day" pill that shows only while the user scrolls. True sticky headers don't combine well with a virtualized, measured list.
- Older messages load when scrolled within 600px of the top; scroll position is restored from "distance from bottom", which works with measured, variable-height rows.
- Quote click: loads older pages until the target is in memory (`ensureLoaded`), then centers and flashes it.
- Mock edit window is 15 minutes, like WhatsApp; Up arrow on an empty composer only edits your last text message inside that window.
- Delete for everyone asks for confirmation in a dialog. The dialog text admits that clients with anti-delete (like this one) may still show it.
- Settings is a full view in the main pane, with the chat list still visible on the left. Esc and Ctrl+, close it.
- Plugin-facing types (`plugin-core/types.ts`) only import `ComponentType` from React. Plugins get narrow `PluginMessage` / `PluginChat` shapes built by adapters, not our internal DTOs, so internals can change without breaking plugins.
- The `settings.sections` slot renders inside Settings → Plugins under "Plugin settings", and that group is hidden when nothing registered.
- The QR code is a fake grid with the right look (finder patterns, quiet zone), drawn as SVG. It stays dark-on-white in dark mode because phones scan inverted codes poorly. Clicking it simulates a scan in the mock.
- The emoji button opens a small fixed grid; a real picker is out of scope for this pass.
- Attach and "Open folder" buttons are present but do nothing until the Go side exists.
- External links in messages use `target="_blank"`. Under Wails they'll need to go through `BrowserOpenURL`, which is a backend concern.
- Two ESLint warnings remain from `react-hooks/incompatible-library` on `useVirtualizer` (TanStack Virtual can't be memoized by the React Compiler). They're warnings, not errors, and expected for that library.
- Screenshots were taken with `playwright-core` driving the system Edge install (no browser download), from a script kept outside the repo so the project has no Playwright dependency.
- Themes are packages: a folder with `manifest.json` and CSS modules. A module can be required, on by default, or off by default; the user's per-module choices live in `settings.themeModules` as `themeId/moduleId`. Splitting a theme this way lets people take, say, Adwaita's widgets without its header bars.
- Built-in themes are bundled with `import.meta.glob(..., { query: '?raw' })` so they work offline in the Wails binary. User themes from disk will arrive from Go in the same `ThemePackage` shape.
- Theme CSS is injected as `<style data-wz-theme>` at the end of `<head>`, so it wins over app CSS at equal specificity without `!important`.
- A user-picked accent (inline on `<html>`) still beats a theme's accent. With no accent picked, the theme's accent is used, and the Appearance page says so instead of highlighting a preset.
- Adwaita uses blue_4 (`#1c71d8`) as its light accent rather than `#3584e4`, so white text on it passes WCAG AA. Accent bubbles are darkened for the same reason.
- WinUI theme: Mica and acrylic are drawn with their solid fallback colors, because the brief rules out blur and translucency. The real Mica backdrop would come from the Wails window (WebView2 transparency), not from CSS.
- WinUI follows Fluent's accent rules: AccentDark1 (`#005fb8`) with white text in light mode, AccentLight2 (`#60cdff`) with black text in dark mode. Accent bubbles use `--wz-accent-fg`, so they switch text color the same way.
- In the WinUI dialog, the destructive action is the accent (primary) button on the left, as in ContentDialog; the close X is hidden when the dialog has its own buttons.
- Several themes can be on at once. They're applied in name order (Adwaita, then WinUI), so the later one wins where they overlap. Mixing modules from different themes works but isn't curated.
- Layout is a separate appearance setting (`panels` / `rail`), set as `<html data-layout>`, not part of a theme. Moving settings into the sidebar and adding an icon rail changes the component tree, which CSS can't do. A theme can ask for a layout with `"layout"` in its manifest, and turning the theme on switches to it once; the user can switch back.
- Rail layout: Chats, Calls, Status, Archived at the top; Settings and profile at the bottom. Calls and Status are honest "not supported yet" panels rather than missing icons, so the rail reads like the familiar one without pretending features exist.
- The rail unread badge counts chats with unread messages (not muted or archived), like the official client, not total messages.
- "New chat" (+) focuses the search field: there's no contact picker yet, and the search placeholder already says "Search or start a new chat".
- The chat list ⋮ menu only has actions that work (archived, mark all read, settings, log out). New group, starred messages, select chats and app lock were left out rather than shown dead.
- Classic Green copies the layout, palette and bubble shapes of the official desktop client but not its logo, name or doodle wallpaper (their artwork); it uses our own dot pattern instead. The light accent is darkened to `#178048` so white text on it passes AA.
- Avatars for names that are just a phone number show a person silhouette instead of digits.
- Profile (your name, about, phone) is its own settings section and backend service (`profile.get/setName/setAbout`), separate from About (app version, disclaimer, links). `Me` in auth stays the account identity; `Profile` is what others see.
- The rail avatar opens Profile directly (`openSettings('profile', true)`); the settings gear opens the section list.
- Profile fields edit in place. While editing, Esc cancels the edit only (the field registers its own layer), a second Esc leaves the page.
- Contact / group info is a panel to the right of the conversation, opened by clicking the header (or ⋮ → Contact info). Under 1100px wide it floats over the conversation instead of squeezing it. It closes when you switch chats and on Esc.
- Info data comes from a new `chats.getInfo(jid)`: about/description, phone, members with admin flags, media/doc/link counts, the 6 latest photos/videos, and counts of what anti-delete and edit history kept. It's refetched when the chat's last message changes.
- The info panel only offers actions that work today: mute, pin, archive, jump to media, open a member's chat, member search. Block, report, clear/export chat, leave group, disappearing messages and invite links need the Go side and were left out rather than shown dead. Instead there's a "Kept by WhatsZori" section with the anti-delete and edit-history counts for the chat.
- Vitest turns CSS imports (even `?raw`) into empty strings, so the theme test only checks that every file a manifest lists exists.
- Logo: a message bubble (rounded square, tail on the right, so it doesn't echo the round WhatsApp bubble) with a monoline Z whose bottom bar is a horizon and an amber sun rising behind it ("zori" = dawns). Slate blue `#3d6fb4` (the default accent) and amber `#f5b860`, no green. Files in `frontend/public/`: `logo.svg` (mark, also the favicon), `avatar.svg` (circular, for profile pictures), `logo-wordmark.svg` (mark + name; follows light/dark via `prefers-color-scheme`), plus PNG exports at 32/192/512 px and the wordmark in light and dark.
- The wordmark letters are hand-drawn monoline strokes matching the Z, not text, so it looks the same everywhere without bundling a font.
- In the app, the logo is an inline `<Logo />` component (copies of the `public/` drawings), not an `<img>`: an SVG image only sees the OS color scheme, so a manually chosen dark theme would get dark lettering on a dark background. Used on the splash, auth card, sidebar header (panels layout), empty state and About.
